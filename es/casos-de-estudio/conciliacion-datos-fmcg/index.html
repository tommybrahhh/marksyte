Cuando tres fuentes no coinciden, el proceso de excepciones se convierte en el producto

Un caso ilustrativo sobre cómo convertir un archivo de proveedor, un ERP y datos de venta del retailer en una visión operativa controlada.

Ver conciliación de datosLeer el caso

Ejemplo ilustrativo · No implica cliente, marca ni resultado comercial

Este caso encaja cuando
  • Tres equipos presentan totales diferentes para el mismo periodo
  • Los IDs de producto, cliente o ubicación no coinciden
  • Las excepciones se resuelven manualmente sin responsable claro
  • Las decisiones se retrasan porque nadie confía en la comparación

La situación

El negocio no necesitaba otro dashboard. Necesitaba una comparación fiable

Un proveedor enviaba expediciones por código de producto, el ERP registraba facturas por SKU interno y un retailer compartía ventas por otra estructura de producto y ubicación. En principio, los números podían compararse, pero las definiciones, los tiempos y los identificadores no estaban alineados.

Este caso es una composición sintética basada en patrones habituales de operaciones FMCG. Sirve para explicar el método, no para atribuir un proyecto o un resultado a un cliente.

01 / Definir

¿Qué debe coincidir exactamente?

Acordar nivel de detalle, periodo, moneda, unidades, estados, claves y significado de una coincidencia válida.

02 / Conciliar

¿Dónde se separan las fuentes?

Comparar totales y registros y clasificar diferencias de tiempo, identificadores, duplicados, datos ausentes o negocio.

03 / Operar

¿Quién resuelve la siguiente diferencia?

Asignar responsable, evidencia, prioridad, estado y ritmo de revisión para que la cola no desaparezca en correos.

Entradas y salidas

Una vista de conciliación que resiste el siguiente ciclo de informes

Registro de fuentes

Archivo de proveedor, extracción del ERP y ventas del retailer con responsable, frecuencia, cierre y límites conocidos.

Tabla de correspondencias

Relaciones entre producto, cliente, ubicación, fecha y unidad con reglas versionadas.

Totales de control

Registros, cantidades, valores, duplicados, claves ausentes y comprobaciones por periodo.

Cola de excepciones

Tipo de diferencia, responsable, prioridad, evidencia, acción propuesta y estado.

Vista de decisión

Totales fiables y advertencias conocidas para reposición, margen, nivel de servicio o revisión de cuenta.

Notas operativas

Definiciones, supuestos, pasos de actualización y reglas de escalado que otro equipo pueda seguir.

Controles y límites

La automatización puede comparar registros. El responsable sigue resolviendo la excepción

El ejemplo parte de hojas estructuradas, consultas de base de datos o herramientas de flujo existentes, no de una plataforma nueva. La automatización puede estandarizar campos, ejecutar controles y mostrar diferencias; no debería sobrescribir datos de origen ni decidir en silencio qué definición de negocio es correcta. El responsable del control mantiene la decisión sobre la regla, la evidencia y el cierre.

Capacidad relacionada

De una comparación fiable a un proceso operativo repetible

Conciliación de datos y controles es la capacidad más directa. El método también se conecta con el mapeo e integración de datos cuando hay que cambiar las estructuras de origen.
